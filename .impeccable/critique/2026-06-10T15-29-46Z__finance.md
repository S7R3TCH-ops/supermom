## Anti-Patterns Verdict

**LLM assessment**: Finance avoids the worst product SaaS tropes — no hero-metric tiles, no gradient text, no side-stripe cards. The 2×2 stat grid with drill-through detail sheet is a genuinely practical pattern. The trend chart uses real data, not fake sparklines. The main personality leak: emoji icons (💰💸👷) as transaction type indicators read as placeholder, not finished product. The Tax Ready card has a generic "AI label + big CTA" structure that edges toward boilerplate but stays on-brand. Overall aesthetic passes.

**Deterministic scan**: Clean — exit code 0, no anti-pattern hits detected in Finance.jsx.

**Visual overlays**: Browser automation unavailable; no overlay injection performed.

## Overall Impression

Finance is the most functionally complete page in the app but is held back by two silent broken CTAs (CSV export, VIEW ALL invoices) and a period toggle that contradicts the design spec. The UX for the core loop — check my numbers, see who owes me — works well. The tax section and invoice section feel parked: visually present but non-functional, which in Sandra's hands means "app is broken."

## What's Working

1. **Drill-through detail sheet** — tapping a stat card opens a focused breakdown. Clean pattern that keeps the main view uncluttered while making every number explorable. The profit breakdown grouping (income / worker costs / expenses) is particularly well thought out.
2. **Privacy mode** — consistently applied across every dollar value in both the main page and the detail sheet. Works silently and completely.
3. **Period toggle + chart sync** — the chart, stats, and activity list all respond to period changes together. No stale data, no partial updates. Feels solid.

## Priority Issues

**[P0] "VIEW ALL INVOICES ›" and "Download CSV" are dead CTAs**
- Why it matters: Both buttons render, look tappable, and do nothing. Sandra will tap "Download CSV" before her accountant meeting and get zero response. She won't file a bug — she'll just conclude the app doesn't work and use a spreadsheet instead. This is trust-destroying.
- Fix: Either wire them up (link invoices button to `/finance/invoices` or a sheet; wire CSV button to the actual export logic), or remove them entirely until the functionality exists. A clearly labeled "Coming soon" or disabled state beats silent failure.
- Suggested command: `$impeccable harden`

**[P1] Period toggle violates design spec**
- Why it matters: DESIGN.md specifies toggle container background = `var(--plum-mid)` (#2C2C2E) with `solid pink` active state. The current code uses `T.card` (white in light mode) with `T.pinkPale` (#FFF9F5) for the active state — a barely-distinguishable tint. In dark mode the active state is `rgba(255,255,255,0.1)` instead of solid pink. Two modes, neither matches spec. The toggle is the primary navigation control on this screen.
- Fix: Replace toggle container with `background: #2C2C2E` (or `var(--plum-mid)`) in all modes. Active button: `background: var(--pink)`, `color: white`. Inactive: `color: rgba(255,255,255,0.55)`.
- Suggested command: `$impeccable polish`

**[P1] Hero section missing pink border-bottom in light mode**
- Why it matters: DESIGN.md rule: "Every dark hero section has `border-bottom: var(--border-hero)` (3px pink). Never skip it." Current code: `borderBottom: mode === 'dark' ? '3px solid #E91E6A' : 'none'`. In light mode the dark hero section has no separator, violating the spec that this border exists to separate the dark hero from the pink logo bar above.
- Fix: Remove the conditional. Apply `borderBottom: '3px solid #E91E6A'` unconditionally, matching the spec and the Admin/Settings pattern.
- Suggested command: `$impeccable polish`

**[P1] Loading state is plain text, not skeleton**
- Why it matters: "Loading finances…" in a bare div breaks the visual continuity. Per product register: "Skeleton states for loading, not spinners in the middle of content." On Sandra's phone, the Finance tab will flash an unstyled gray text string on every navigation.
- Fix: Render the stat grid and chart area as skeleton cards (use `background: T.cardBorder` animated shimmer) while `loading && allJobs.length === 0`.
- Suggested command: `$impeccable harden`

**[P2] Transaction list silently caps at 20**
- Why it matters: `transactions.slice(0, 20)` with no "showing 20 of 31" label means Sandra does month-end accounting on an incomplete list without knowing it. Worker costs + expenses + jobs can easily exceed 20 in a busy month.
- Fix: Show all items, or add a "Showing 20 of {total}" row with a "Show all" button. Given the mobile context, showing all (with virtualization if needed) is simpler.
- Suggested command: `$impeccable harden`

## Persona Red Flags

**Casey (Distracted Mobile User — Sandra between jobs):**
- "+ ADD EXPENSE" button: 4px top+bottom padding, 10px font ≈ ~22px tap target. Half the WCAG minimum. Sandra will mis-tap this constantly one-handed.
- "VIEW ›" badge on stat cards: 9px text, opacity 0.7, positioned bottom-right. On a 390px phone, the touch target is the whole card (good), but the affordance is invisible — Sandra may not discover the drill-through exists.
- CSV export button will do nothing silently mid-tax-season. No spinner, no toast, no error. She'll think the download happened and nothing will be in her Downloads folder.

**Riley (Stress Tester):**
- Period = "All Time" with only 1 month of data → chart shows "Not enough data for this period" while the stats correctly show real revenue/expenses. Inconsistency: the numbers are there but the chart claims they aren't.
- "Formal Invoices" cuts off at 3 with a dead "VIEW ALL" button. If Sandra has 4+ invoices, the 4th is invisible with no reachable path.
- The `toLocaleDateString()` call in the invoices list (line 510) uses browser timezone, not `America/Toronto`. Dates will shift for non-Toronto users or in DST edge cases.

**Sandra (Solo operator, non-technical):**
- Outstanding balance is visible, tappable, and opens a list. But there's no "send nudge" action inside the detail sheet — she'd have to remember the client's name, exit Finance, navigate to Clients, find the client, and message. The outstanding workflow is the most urgent real-world action on this screen and it has no completion path.

## Minor Observations

- Emoji icons (💰 💸 👷) as transaction type indicators: inconsistent with the SVG icon treatment throughout the rest of the app; should be replaced with a small colored SVG or the colored dot pattern used elsewhere.
- Invoice `toLocaleDateString()` at line 510 uses browser timezone, not `America/Toronto`. Change to `toLocaleDateString('en-CA', { timeZone: 'America/Toronto', ... })`.
- Chart SVG axis labels use `fontFamily: 'system-ui, -apple-system, sans-serif'` instead of `T.font` (Inter). Minor visual inconsistency but noticeable at 8px.
- StatCard `$` sign and amount are in separate spans, so `$` uses a plain `fontWeight: 700` color while the number uses Fraunces — the split is fine visually but the `$` should also be Fraunces for consistency with DESIGN.md's "Dollar amounts always: Fraunces, tabular-nums."
- "✦ CSV Export Ready" label in Tax Ready card repeats information already communicated by the button. Either drop the label or make it say something the button doesn't (e.g., the date range covered).
- `workerCosts` sub-label in StatCard shows only when `workerCosts > 0` — good. But the formatting `-$${workerCosts.toFixed(0)}` drops HST and rounds, which could mislead Sandra about her actual deduction amount.

## Questions to Consider

- The Outstanding stat card shows what's owed but has no action path to collect it — should tapping Outstanding open a "nudge all" or "send invoice" flow rather than just a list?
- The Finance page has no relationship with the Invoices route (`/i/:id`). Should "Formal Invoices" be a link to a proper invoice list page, or should the section be removed until that exists?
- Does Sandra need a month-over-month comparison (e.g., "↑12% from last month") to feel confident in the trend chart, or is the chart itself sufficient?
