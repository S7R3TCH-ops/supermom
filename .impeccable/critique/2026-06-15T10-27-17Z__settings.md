### Anti-Patterns Verdict

**LLM assessment:** No severe AI-slop tells. The page is clean and functional. The hero with Fraunces "Settings" heading and radial pink glow is on-brand. Card grouping is logical. Where the page falls into pattern-by-reflex: every interactive element label is ALL CAPS — a systemic capitalization habit, not a design choice.

**Deterministic scan:** 1 finding — `transition: height` on the keyboard spacer div (line 522). Same layout-thrash issue found and fixed on other pages but missed here.

### Overall Impression

Functionally solid — dirty-state detection, progressive disclosure on HST, good field grouping — but has several consistency debts relative to the polish passes already completed on other pages. Three P1 issues (window.confirm for destructive action, outline:none on all inputs, avatar div not keyboard-accessible) were fixed elsewhere and just weren't propagated here.

### What's Working

1. **isDirty banner** — Detecting unsaved changes and floating a clear pill at the top is excellent UX for a settings page.
2. **ToggleSwitch semantics** — Has role="switch", aria-checked, keyboard-accessible. Done right.
3. **Progressive HST disclosure** — HST number field only appears when tax_enabled is on.

### Priority Issues

**[P1] window.confirm() on Reset All Data**
- **What:** Line 243 uses window.confirm() for a destructive action that permanently deletes all data.
- **Why it matters:** Fixed in JobDetailSheet (v0.12.50). Even more critical here — Reset All Data is irreversible. Sandra could accidentally confirm on a stray tap.
- **Fix:** Two-tap in-app confirm pattern used in JobDetailSheet.

**[P1] outline: none on all inputs, no replacement**
- **What:** inputStyle at line 288 sets outline: 'none' with nothing to replace focus visibility.
- **Why it matters:** Every form input is invisible to keyboard users when focused. WCAG 2.1 AA failure. Fixed in NewJobSheet (v0.12.55) and JobDetailSheet (v0.12.50).
- **Fix:** Remove outline: 'none' or add CSS focus ring via className.

**[P1] Avatar div is not keyboard-accessible**
- **What:** Line 357 — div onClick with "EDIT" overlay. Not focusable, not announced to screen readers, no ARIA label.
- **Fix:** Change to button type="button" aria-label="Change avatar photo".

**[P1] All-caps button labels throughout**
- **What:** Every interactive element label is ALL CAPS: SAVE SETTINGS, UPDATE PASSWORD, SIGN OUT, MANAGE, CONNECT, RECONNECT, RESET ALL DATA, and loading states (UPDATING..., SAVING CHANGES...).
- **Why it matters:** Prior polish passes on other pages converted these to sentence case.
- **Fix:** Convert to sentence case throughout.

**[P2] Password visibility toggle tap target too small**
- **What:** ToggleBtn has padding: 4 around a 16x16px icon — total ~24x24px. Minimum 44x44px not met.
- **Fix:** Expand to padding: '14px 14px' or set minWidth/minHeight: 44.
