**v0.13.116** (LIVE 2026-10-14, `fe3890e`, branch `fix/gcal-event-id-integrity` merged ff to main; audited PASS-WITH-NITS, nits fixed; live bundle contains the sha): Sandra's "moved one Katie appointment, Google shows both days" (request `ade5ec41`) and Joel's same symptom on the QA account.
- **Cause, Sandra (data, verified 2026-10-13 against prod):** every Katie series job (template `31d66a`, created 08-14) shared ONE `ai_context.gcal_event_id` (`oltsg8st`), so each save dragged that single Google event between dates, and 7 old 08-14 "Hourly chores rate - Katie" events (09:00 Mondays) had no job pointing at them. QA case not reproduced: its only orphan was event `rcg8f94t` (10-07 12:00) whose job row no longer exists.
- **Code weaknesses fixed:** (1) `jobsRepo.js` `updateJob` 'this' wrote the edit sheet's stale `ai_context` snapshot wholesale, so a missing/old `gcal_event_id` made the next sync insert a second event; it now re-reads the row and keeps the server-owned keys (`gcal_*`, `occurrence_index`, `template_id`) via `src/lib/jobAiContext.js` `mergeAiContextForJobSave` (a non-system key left out of the patch is still cleared, which is how JobDetailSheet drops `drive_to` on reschedule). (2) Series saves no longer propagate `gcal_*`/`occurrence_index`/`template_id`/`drive_to`/`drive_to_live`/`clock_in_time` to sibling jobs; `createRecurringSeries` strips them from the template payload. (3) `api/sync/gcal.js`: new events use a deterministic Google id (job uuid without dashes), so a second/concurrent insert gets 409 and updates in place and a job that lost its stored id re-finds its own event; it will not reuse or delete an event another live job still holds (heals shared series ids one job at a time); `ai_context` is merged onto a fresh read and a failed read/write throws instead of wiping keys; delete tolerates 404/410 and falls back to the deterministic id; a 409 whose update is refused (410) falls back to a fresh event; `status:'confirmed'` on every upsert; fixed `job` being out of scope in the `token_expired` catch (that status never persisted before).
