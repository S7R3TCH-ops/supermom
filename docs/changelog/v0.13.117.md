## Current version: 0.13.117 - Oct 21, 2026 (invoice email button no longer cries wolf; round logo badge in emails)

**v0.13.117** (not yet pushed/live when written): Sandra's bug request `142fec00` ("invoice didn't send").

- **Evidence (prod, job `5e45f60d`):** `invoice_sent_at` = 2026-10-16T00:25:02Z, Sandra reported "didn't send" at 00:31:19Z. `api/invoice.ts` sets the stamp only after `sendMail` resolves, then returns 200, so the email went out and the button showed "Failed - retry" anyway. Cause of the lost response (iOS PWA fetch abort, timeout, flaky network) is unknowable from the data: plausible, not confirmed.
- **Part a, `src/pages/InvoiceView.jsx` `handleEmail`:** snapshots `invoiceSentAt`/`receiptSentAt` before the POST. On any failure it calls `reload()` and compares both stamps to the snapshot (change, not clock times, so no clock-skew issue; the server decides receipt vs invoice). Changed -> shows "Sent!" like a normal success. Unchanged: a real HTTP error response (4xx/500 with a server message) keeps "Failed - retry"; no HTTP response, a gateway/timeout status (408/502/503/504), or a failed re-read shows the new amber state "Couldn't confirm - check Sent mail before resending" (clickable, resets to idle after 10s). The decision lives in the pure helper `src/lib/invoiceEmailOutcome.js` (`resolveEmailFailureOutcome`, tests in `invoiceEmailOutcome.test.js`). `api/invoice.ts` send order is unchanged.
- **Logging:** every failure writes a client `error_logs` row via `logClientError` (type `invoice_email_send`: outcome, invoiceId, HTTP status, elapsed ms, `document.visibilityState` at start and at failure, whether the re-read failed). Recipient email addresses are scrubbed from the message, never logged.
- **Part b, white box around the logo in emails:** `logo-final-white-bg.png` is an opaque 1024x1024 white square on the pink/green header. Added `border-radius:50%` (round white badge, mock approved) to the `<img>` in `api/invoice.ts`, `api/_lib/brandedEmail.js` (was `8px`) and `api/briefing/daily.js` (paused briefing). `api/_lib/invoicePdf.ts` and the InvoiceView document are untouched (mirror rule not triggered). Test: `api/_lib/brandedEmail.test.js` (the other two templates are not exported, so not covered by a test).
- **Not device-confirmed:** needs a real-iPhone pass once live. The lost-response path is covered by unit tests of the decision only, not a reproduced network abort.
