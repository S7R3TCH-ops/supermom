## Current version: 0.13.117 - Oct 21, 2026 (invoice email button no longer cries wolf; round logo badge in emails)

**v0.13.117** (not yet pushed/live when written): Sandra's bug request `142fec00` ("invoice didn't send").

- **Evidence (prod, job `5e45f60d`):** `invoice_sent_at` = 2026-10-16T00:25:02Z, Sandra reported "didn't send" at 00:31:19Z. `api/invoice.ts` sets the stamp only after `sendMail` resolves, then returns 200, so the email went out and the button showed "Failed - retry" anyway. Cause of the lost response (iOS PWA fetch abort, timeout, flaky network) is unknowable from the data: plausible, not confirmed.
- **Part a, `src/pages/InvoiceView.jsx` `handleEmail`:** snapshots `invoiceSentAt`/`receiptSentAt` before the POST. On any failure it calls `reload()` and compares both stamps to the snapshot (change, not clock times, so no clock-skew issue; the server decides receipt vs invoice). Changed -> shows "Sent!" like a normal success. Unchanged: a real HTTP error response (4xx/500 with a server message) keeps "Failed - retry"; no HTTP response, a gateway/timeout status (408/502/503/504), or a failed re-read shows the new amber state "Couldn't confirm - check Sent mail before resending" (clickable; stays up as the double-send warning until the next click; the 'sent' 4s reset timer is cleared at the start of each send so it can't fire mid-send). The decision lives in the pure helper `src/lib/invoiceEmailOutcome.js` (`resolveEmailFailureOutcome`, tests in `invoiceEmailOutcome.test.js`). `api/invoice.ts` send order is unchanged.
- **Audit fix (A1, the recheck could never see 'sent' without it):** `api/invoice.ts` `handleJsonRead` (the `/i/:id` page's read) did not select `invoice_sent_at`/`receipt_sent_at` on `jobs`, and `decorateInvoiceWithBalances` spreads the invoice so `invoice_jobs` passes through untouched. The columns are now in that select only (send order, `handleDownload`, `handleEmail` untouched). Side effect: the existing "Invoice sent <date>" / "Receipt sent <date>" header lines and the settle panel gate (`showSettlePanel` needs a sent stamp) were dead for the same reason and will start showing/working on the invoice page. Pre-existing, now fixed by this change; worth a look on a real device.
- **Logging:** every failure writes a client `error_logs` row via `logClientError` (type `invoice_email_send`: outcome, invoiceId, HTTP status, elapsed ms, `document.visibilityState` at start and at failure, whether the re-read failed). Recipient email addresses are scrubbed from the message, never logged.
- **Part b, white box around the logo in emails:** `logo-final-white-bg.png` is an opaque 1024x1024 white square on the pink/green header. Added `border-radius:50%` (round white badge, mock approved) to the `<img>` in `api/invoice.ts`, `api/_lib/brandedEmail.js` (was `8px`) and `api/briefing/daily.js` (paused briefing). `api/_lib/invoicePdf.ts` and the InvoiceView document are untouched (mirror rule not triggered). Test: `api/_lib/brandedEmail.test.js` (the other two templates are not exported, so not covered by a test).
- **Not device-confirmed:** needs a real-iPhone pass once live. The lost-response path is covered by unit tests of the decision only, not a reproduced network abort.
