## v0.13.119 - Oct 24, 2026 (iOS PWA invoice PDF share)

Branch `fix/sandra-invoice-pdf-onepage`. Not pushed, not live.

**Bug (Sandra, iPhone, installed PWA):** "Download PDF" on the invoice page was `<a href="/api/invoice?id=..." download>` and the API replies `Content-Disposition: attachment`. In an installed iOS PWA this navigates the only window to the PDF with no browser chrome (no back, no save), so she had to kill the app.

**Fix:**
- New `src/lib/pdfShare.js` (tests in `src/lib/pdfShare.test.js`): `isStandalonePwa()`, `fetchPdfFile()`, `canShareFile()`, `shareFile()`.
- `src/pages/InvoiceView.jsx`: when running as an iOS home-screen PWA (`navigator.standalone === true`), "Download PDF" is a button. Tap -> "Preparing..." -> fetch the PDF -> `navigator.share({files})` (Save to Files, Print, Mail...). The window never navigates.
  - User dismissing the sheet (`AbortError`) is treated as cancelled: no error, no fallback.
  - If iOS refuses the share because the awaited fetch used up the tap's user activation (`NotAllowedError`), the fetched file is kept and the button reads "Ready - tap to share"; that second tap calls `navigator.share` synchronously. A second refusal, an unsupported device, or any fetch/share error shows "Couldn't prepare the PDF. Use Email, or try again."
  - Everything else (desktop, Android incl. installed PWAs, browser tabs, clients opening `/i/:id`): the original anchor is rendered unchanged. Detection is deliberately `navigator.standalone` only, not `display-mode: standalone`.
  - Prepare/share failures are logged to `error_logs` (`type: invoice_pdf_prepare` / `invoice_pdf_share`) via `logClientError`, same pattern as the email send.
- Filename matches the server's: `${last_name || 'Client'}_${docLabel}_${invoice_number || docLabel}.pdf`. (If an invoice has no number the server falls back to `Invoice` rather than the label; the only difference is the saved name for a receipt with no number.)
- `api/invoice.ts` and `api/_lib/invoicePdf.ts` untouched; no new serverless function.

**UNVERIFIED on a real iPhone (needs a phone test by Joel/Sandra):**
- That the share sheet opens from the installed PWA and "Save to Files" produces a working 1-page PDF.
- Whether iOS actually expires user activation after the fetch (decides if the "Ready - tap to share" step is ever seen).
- A held "ready" file is discarded if the doc flips between invoice and receipt (name changes).

**Tests:** unit tests cover iOS-only standalone detection (display-mode alone is false), share ok, `AbortError` = cancelled, `NotAllowedError` = needs-tap, unsupported, fetch non-ok / non-PDF, and that `navigator.share` is called synchronously.
